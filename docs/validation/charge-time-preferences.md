# Charge time preferences

Charge done-by time is a per-scooter local preference. Editing it while offline requires a selected scooter but no connection, charger, estimate or Bluetooth write. Offline changes apply on the next explicit activation; reconnect alone never applies them. The active toggle tile retains the actual armed deadline while the picker shows the saved preference. In-flight transactions block concurrent edits.

When connected and done-by is active, accepting a new time explicitly calculates and confirms a new native start. It uses fresh charging ETA, or reuses the captured ETA during a future owned scheduled pause only when fresh SOC and charge limit exactly match their captured values. Missing/stale/changed readings or legacy plans without captured SOC require fresh charging data. Preflight rejection leaves the old plan and preference intact; partial writes report their actual state. Clock, time and enable confirmation, transport/profile/timezone guards and no automatic reconnect writes remain in force. This is one action per edit, not a background adjustment loop. Automatic OFF/sample/ON fallback is deferred: interruption after OFF could otherwise leave charging resumed.

The manual start preference is stored separately from the programmed start. Charge start remains muted and locked while done-by is active, displaying the manual preference. Explicitly disabling done-by confirms schedule OFF, then confirms clock and manual-time restoration. It never turns Scheduled charging on. Expired manual times use their next occurrence. If OFF fails, the plan stays active; if restoration fails after OFF, the plan stays off and the app reports the partial result. Reconnect does not retry writes.

Persistence v3 retains manual time, the last attempted calculated wire timestamp and captured SOC. It decodes v1/v2 records without inventing a missing manual preference or captured SOC. A genuine native manual-time edit updates the saved manual preference; delayed calculated-write readback cannot overwrite it, including after restart. When no saved manual time exists, disabling only cancels the schedule and the user can set Charge start once.

Validation covers offline edits without commands, explicit connected active edits with live and validated paused estimates, rejected stale/changed estimates, retained manual time, external manual changes, delayed calculated readback, successful restoration, failures at each stage, reconnect/profile changes, legacy migration and previously enabled manual schedules remaining off. The native fixture exercises actual time pickers, disabled rows, dashboard tiles, simulator commands and controller callbacks at compact and unfolded sizes. It refuses physical phones and uses Bluetooth-disabled synthetic data. Physical charger behavior remains unverified.
